# Итоговый отчёт INDUSTRIA TWIN

Дата проверки: 09.11.2026 (повторная проверка после второй итерации). Среда: macOS (arm64), Node.js 24.18, npm 11.16.

## 1. Реализованные возможности

* **Симулятор** (`src/domain/simulation`) — дискретно-событийный движок без зависимостей от UI: календарь событий с детерминированным вторичным ключом, очереди FIFO, ресурсы ограниченной вместимости, контроль качества с ограниченным числом доработок и списанием, НЗП на конец горизонта, интегралы занятости, воспроизводимый ГПСЧ (sfc32/splitmix32), репликации с 95% ДИ, журнал событий и кадры состояния.
* **Модель данных** — Prisma/SQLite, 20 моделей, миграция, seed. Демонстрационные прогоны рассчитываются движком при заполнении.
* **API** — 17 файлов маршрутов (21 обработчик HTTP-методов) с Zod-валидацией, ролями, проверкой Origin, ограничением частоты и единым форматом ошибок.
* **Авторизация** — роли admin / engineer / viewer, bcrypt, подписанный cookie и серверная сессия с отзывом.
* **Интерфейс** — дашборд (KPI с ДИ, узкое место, таблица участков, 4 графика, структура стоимости), интерактивная мнемосхема, студия сценариев (создание, копирование, редактирование, удаление, запуск, аналитическая подсказка ρ), сравнение до трёх альтернатив с базовым (Δ абс./отн., различимость по Уэлчу, смещение узкого места, отличия параметров, графики с ДИ, сравнение по участку), документация модели, администрирование.
* **3D-тур** — процедурный цех (станки ЧПУ, сборочные посты с порталами, испытательные стенды, стеллажи, конвейеры, паллеты, насосы, сигнальные колонны, напольная разметка). Изометрический обзор, вид сверху, 8 ракурсов с плавными перелётами, выбор мышью и касанием, 7 точек интереса, экскурсия из 7 остановок (вручную или автоматически), режим воспроизведения прогона по кадрам из журнала событий, адаптивное качество, резервный 2D-план без WebGL.
* **Единый источник истины** — один `stationId` во всех слоях; `selectStation(stationId)` синхронизирует мнемосхему, таблицы, графики, 3D и панель метрик; выбор сохраняется в URL при переходах.

### Улучшения второй итерации (движок 1.1.0)

* **Общие случайные числа (CRN) и парное сравнение.** У каждого источника случайности свой поток: поступления; длительность операции (изделие, участок, номер посещения); исход контроля (изделие, номер проверки); отказы и ремонты участка. В сценариях с одинаковым seed изделие №k получает одинаковые «случайности», поэтому сравнение строится по разностям внутри пар репликаций. Полуширина 95% ДИ разности сократилась в 5–10 раз: эффекты, которые раньше были «статистически неразличимы» (например, −7…−10 мин цикла от дополнительного поста), теперь различимы. Для несопоставимых прогонов (разный seed, старая версия движка) автоматически применяется интервал Уэлча; метод указывается в интерфейсе и API (`pairedFlags`, `method`).
* **Отказы оборудования (MTBF/MTTR).** Неупреждающая модель: отказы участка — пуассоновский поток с интенсивностью вместимость/MTBF, ремонт экспоненциальный со средним MTTR. Новые показатели: отказы, время в ремонте, доступность. Статус участка и узкое место определяются по эффективной загрузке (занятость + доля времени в ремонте). В базовом сценарии заданы отказы станков ЧПУ (600/30 мин) и стенда (900/20 мин); с ними узким местом становится механообработка, хотя без отказов им выглядела бы сборка. Новый сценарий «Программа ТОиР (TPM)». Миграция `20261109160000_equipment_failures`.
* **Советник по ресурсам** (`src/domain/analysis/advisor.ts`, `GET /api/runs/[id]/advice`, блок на дашборде). Автоматически моделирует 7 вариантов «+1 ресурс» (каждый участок и два самых загруженных вместе) с тем же seed, оценивает парно, отсекает изменения < 1% как практически несущественные, ранжирует: «рекомендуется», «быстрее, но дороже», «нет заметного эффекта», «дороже без эффекта», «ухудшает». Кнопка «Проверить и сравнить» создаёт сценарий, рассчитывает его и открывает сравнение. Результаты кэшируются по снимку параметров.
* **Вывод для руководителя в сравнении**: правило по различимым изменениям ключевых показателей (цикл, выпуск, стоимость единицы, НЗП), смещение узкого места и рекомендация; «±» в ячейках таблицы.
* **Кейсы точек интереса в 3D-туре** (`POI_CASES`): карточка «вопрос → рассчитанные до/после → переход к сравнению и к процессу в этом сценарии». Числа вычисляются из последних прогонов, а не хранятся в карточке.
* **3D: отказы в воспроизведении** — единица оборудования в ремонте обозначена ограждением с сигнальной лентой, выноской «Ремонт» и красной секцией сигнальной колонны; в табличке участка — «N в ремонте». Кадры состояния содержат третий элемент — число единиц в ремонте.
* **Отчёты**: выгрузка сравнения в CSV (Excel, кириллица), печать / PDF дашборда и сравнения со стилями печати.
* **Кривая пропускной способности** (`capacity.ts`, `GET /api/runs/[id]/capacity`, блок «Запас мощности» на дашборде): 10 точек спроса 60–150% × 10 репликаций с общими случайными числами (кривая гладкая, монотонная); два графика без второй оси — средний цикл и выпуск с полосой 95% ДИ, отметки «сейчас» и «предел»; аналитический предел мощности и ограничивающий участок; таблица значений. Для базового сценария: предел ≈ 5,37 задания/ч (сборка) — текущий спрос 5,5 уже выше установившейся мощности на 2,3%, НЗП растёт в течение смены; при +20% спроса выпуск растёт с 68,9 до 73 шт., цикл — с 145 до 188 мин.
* **Маршруты 3D-тура для аудиторий**: обзорный; «Как рождается насос» (абитуриенты и студенты); «Где теряются время и деньги» (руководство, партнёры, заказчики — по кейсам); «Первый день в цехе» (новые сотрудники — зоны, сигналы оборудования, действия при отказе). Выбор сохраняется в URL (`?tour=`).
* **Движение изделий в воспроизведении** (`ReplayFlow`): непрерывное модельное время вместо скачков по 5-минутным кадрам; по журналу событий насосы движутся между участками через конвейер, списанные выделены красным. Транспорт в модели мгновенный — анимация иллюстративна и так подписана.
* **Импорт и экспорт данных** (`scenarioExchange.ts`, панель «Данные сценария» в студии): сценарий целиком в JSON и таблица участков в CSV (разделитель «;», десятичная запятая, BOM для Excel). Заполненная таблица загружается обратно с проверкой — ошибки показываются с номером строки, импорт всегда создаёт новый сценарий. Это путь подключения данных организаторов или фактических данных цеха без интеграций с ERP/MES.
* **Управление пользователями** (раздел «Администрирование»): создание, смена роли, блокировка, задание пароля (не короче 10 символов, буквы и цифры), удаление. Блокировка и смена пароля сразу отзывают сессии; нельзя заблокировать, понизить или удалить себя и последнего администратора.
* **Журнал аудита** (модель `AuditLog`, миграция `20261109200000_audit_log`): входы, в том числе неуспешные, выход, действия со сценариями, запуски, удаление прогонов, действия с пользователями; фильтр по типу; хранение 180 дней. Только логины-псевдонимы; при удалении учётной записи её записи обезличиваются (152-ФЗ).
* **Период разгона** (параметр сценария `warmupMin`, миграция `20261110090000_warmup`): в момент окончания разгона движок обнуляет накопители, показатели нормируются на окно наблюдения. По умолчанию 0 — демонстрационные результаты не меняются (проверено тестом на побитовое совпадение).
* **Смена собственного пароля** (`/account`, `POST /api/auth/password`): нужен текущий пароль, другие сессии отзываются, попытки ограничены.
* **Исправления по итогам автоматического анализа безопасности**: строгая проверка адреса возврата после входа (`/\host` и протокол-относительные адреса отклоняются); вход защищён замедлением вместо блокировки — одна одновременная попытка на логин и нарастающая задержка после 5 неудач (до 5 с), поэтому параллельный перебор невозможен, а посторонний не может заблокировать чужую учётную запись; жёсткий лимит по адресу — только за доверенным прокси (`TRUST_PROXY=1`); адрес возврата проверяется и после нормализации (`/.//host`); в аудит не пишется текст несуществующего логина и адрес; предел вычислительной стоимости советника и кривой мощности (422); защита CSV от формул.
* **Инженерная культура**: ESLint (правила Next.js и TypeScript, 0 замечаний) и CI в GitHub Actions — lint, typecheck, тесты, сборка, e2e на каждый push; открытый репозиторий https://github.com/moonqerx-droid/industria-twin.
* **Безопасность входа**: лимит считает только неуспешные попытки, успешный вход сбрасывает счётчик (раньше 11 успешных входов подряд блокировали учётную запись на 5 минут).
* **Исправления**: на мобильных длинные названия прогонов в выборе прогона расширяли страницу на 17 px (браузер расширял layout viewport, касания промахивались); проверка адаптивности в e2e усилена; 3D-сцена в туре закреплена при прокрутке длинной правой колонки; корень трассировки Next.js задан явно.

Числа рассчитаны движком и меняются при изменении параметров, они не зашиты в интерфейс. Как их читать: выпуск ограничен входящим потоком, поэтому добавление ресурса в основном сокращает цикл и НЗП. Без CRN ни одно из изменений цикла, кроме роста спроса, не было бы статистически различимо.

## 4. Известные ограничения

* Модель не учитывает переналадки, смены и перерывы, транспортное время, приоритеты и партии. Отказы оборудования моделируются упрощённо (неупреждающе, экспоненциальные наработка и ремонт, без затрат на ремонт сверх ставки ресурса). Период разгона по умолчанию входит в статистику, его можно исключить параметром сценария.
* Все данные синтетические. Для реального цеха модель нужно откалибровать по фактическим данным.
* Ограничитель частоты хранится в памяти одного процесса; для нескольких экземпляров нужно внешнее хранилище.
* Неуспешные прогоны не сохраняются в БД: ошибка возвращается клиенту (422/500), хотя статус `failed` в схеме предусмотрен.
* Восстановления доступа без администратора нет (по замыслу: e-mail не хранится). Журнал аудита хранится в той же БД, что и данные. Состояние ограничителей входа хранится в памяти одного процесса.
* ESLint не настроен; качество кода контролируют строгий TypeScript и тесты.
* Производительность 3D измерена только косвенно: e2e-тесты и адаптивный `PerformanceMonitor`. Значения FPS на реальных устройствах не замерялись и не заявляются. Ручная проверка на слабом телефоне и планшете не проводилась.
* Внешние GLB-модели и фото/видео для точек интереса не подключены: медиа точек — процедурные ракурсы сцены (`isPlaceholder`).
* Mermaid-диаграммы не проверялись рендерером; BPMN проверен только на корректность XML, в Camunda Modeler не открывался.
* Особенности среды при проверке: `prisma migrate reset` заблокирован для автоматизированного агента, поэтому тестовые БД пересоздаются удалением файла и `migrate deploy`. Штатный `playwright install` зависал на распаковке, поэтому браузер для e2e распакован вручную из официального архива Playwright в `node_modules/playwright-core/.local-browsers` (см. README).
* Меры по 152-ФЗ — технические меры минимизации данных, а не заключение о полном соответствии закону.
