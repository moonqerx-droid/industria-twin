# INDUSTRIA TWIN

[![CI](https://github.com/moonqerx-droid/industria-twin/actions/workflows/ci.yml/badge.svg)](https://github.com/moonqerx-droid/industria-twin/actions/workflows/ci.yml)

Демонстрационный прототип для хакатона «Цифровой двойник предприятия и 3D-туры по производству»: дискретно-событийная модель условного цеха сборки насосов, студия сценариев, сравнение «до/после», дашборды и интерактивный 3D-тур, связанные одним набором идентификаторов участков.

> Все производственные данные синтетические и служат только для демонстрации.

## Требования

* Node.js ≥ 20.9 (проверено на 26.13), npm ≥ 10
* Доступ в интернет при первой установке зависимостей и сборке (шрифт Golos Text скачивается next/font)

## Запуск

```bash
npm install
```

```bash
cp .env.example .env
```

Задайте в `.env` значение `SESSION_SECRET` (не короче 32 символов), например результатом `openssl rand -hex 32`.

```bash
npm run setup
```

```bash
npm run build && npm start
```

Приложение: <http://localhost:3000>. Режим разработки: `npm run dev`.

`npm run setup` применяет миграции (`prisma migrate deploy`) к `prisma/dev.db` и заполняет базу (`prisma/seed.ts`); seed запускает симулятор для шести демонстрационных сценариев. Повторный `npm run db:seed` очищает и заново заполняет демонстрационные данные.

> Примечание по e2e: если `playwright install` зависает на распаковке, браузер можно поставить в каталог проекта: `PLAYWRIGHT_BROWSERS_PATH=0 npx playwright install chromium-headless-shell` и запускать тесты с той же переменной (`PLAYWRIGHT_BROWSERS_PATH=0 npm run test:e2e`).

## Демонстрационные учётные записи

| Логин | Пароль | Роль | Права |
|---|---|---|---|
| `admin` | `Admin#Twin2026` | Администратор | всё, удаление прогонов, пользователи |
| `engineer` | `Engineer#Twin2026` | Инженер-технолог | сценарии, запуск моделирования |
| `viewer` | `Viewer#Twin2026` | Наблюдатель | только просмотр |

Пароли только для локальной демонстрации; переопределяются переменными `DEMO_ADMIN_PASSWORD`, `DEMO_ENGINEER_PASSWORD`, `DEMO_VIEWER_PASSWORD` перед `npm run db:seed`. В БД хранятся bcrypt-хеши.

## Команды

| Команда | Назначение |
|---|---|
| `npm run lint` | ESLint (правила Next.js и TypeScript) |
| `npm run typecheck` | Проверка TypeScript (strict) |
| `npm test` | Модульные и интеграционные тесты (Vitest, отдельная БД `prisma/test.db`) |
| `npm run test:e2e` | Playwright smoke и адаптивность (нужны `npm run build` и `npx playwright install chromium-headless-shell`; БД `prisma/e2e.db`, порт 3100) |
| `npm run report:scenarios` | Таблица результатов демонстрационных сценариев из движка |
| `npm run verify` | lint + typecheck + тесты + сборка |

CI (GitHub Actions, `.github/workflows/ci.yml`, Ubuntu 24.04) на каждый push и pull request выполняет lint, typecheck, все тесты, сборку и e2e (desktop, tablet, mobile); таблица демонстрационных сценариев публикуется в сводке запуска.

## Разделы приложения

| Путь | Содержание |
|---|---|
| `/dashboard` | KPI, узкое место (с учётом отказов), состояние участков, **советник по ресурсам**, **запас мощности**, графики загрузки, очередей, НЗП и выпуска, структура стоимости, печать |
| `/process` | Интерактивная мнемосхема с метриками узлов и переходом в 3D |
| `/scenarios` | Студия сценариев: создание, копирование, редактирование, запуск, импорт и экспорт (CSV, JSON) |
| `/compare` | Сравнение базового и альтернативных прогонов: парное (CRN) или Уэлча, вывод для руководителя, CSV, печать |
| `/factory` | 3D-тур: 4 маршрута для аудиторий, точки интереса с кейсами, воспроизведение прогона с движением изделий и отказами, план 2D |
| `/documentation` | Модель, данные, формулы, ограничения |
| `/admin` | Управление пользователями, права, журнал аудита, прогоны (только администратор) |

## Ключевые возможности второй итерации

* **Общие случайные числа и парное сравнение** — в сценариях с одинаковым seed изделие №k получает одинаковые длительности операций и исход контроля; доверительный интервал разности строится по парам репликаций и в 5–10 раз уже, поэтому реальные эффекты (−7…−10 мин цикла) отличаются от шума.
* **Отказы оборудования (MTBF/MTTR)** — доступность, время в ремонте, учёт в узком месте; сценарий «Программа ТОиР»; в 3D-воспроизведении станок в ремонте обозначен ограждением и выноской.
* **Советник по ресурсам** — автоматическая проверка 7 гипотез «+1 ресурс» и переход «рекомендация → сценарий → сравнение» в один клик.
* **Запас мощности** — кривая цикла и выпуска при спросе 60–150% с аналитическим пределом мощности.
* **Маршруты 3D-тура для разных аудиторий** и **движение изделий** в воспроизведении прогона.
* **Период разгона** — исключение старта с пустого цеха из статистики (параметр сценария).
* **Смена собственного пароля** на странице «Учётная запись».
* **Импорт и экспорт данных**: таблица участков CSV для заполнения в Excel, сценарий целиком в JSON.
* **Управление пользователями и журнал аудита** для администратора (152-ФЗ: только псевдонимы, обезличивание при удалении).
* **Вывод для руководителя** в сравнении, **кейсы** точек интереса 3D-тура с рассчитанными «до/после», **экспорт CSV** и **печать / PDF**.
