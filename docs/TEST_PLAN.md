# План тестирования INDUSTRIA TWIN

Документ описывает стратегию проверки ключевой функциональности и перечень автоматизированных и ручных проверок. Идентификаторы требований (BR/FR/NFR) — по [TZ.md](TZ.md).

## 1. Уровни тестирования

| Уровень | Инструмент | Файлы | Что проверяется | Окружение |
|---|---|---|---|---|
| Модульный | Vitest 3 | `tests/unit/engine.test.ts`, `tests/unit/analysis.test.ts` | Движок ДСМ, ГПСЧ, распределения, календарь событий, статистика, поиск узких мест, сравнение | Без БД, без сети |
| Интеграционный | Vitest 3 | `tests/integration/api.test.ts` | Route Handlers API + сервисы + Prisma на изолированной БД `prisma/test.db` | Глобальная подготовка `tests/integration/global-setup.ts`: удаление файла test.db, `prisma migrate deploy`, seed |
| Сквозной (E2E) | Playwright | `e2e/smoke.spec.ts`, `e2e/responsive.spec.ts` | Пользовательские маршруты в браузере, адаптивность, резервный режим без WebGL | Production-сборка (`next start`, порт 3100), отдельная БД `prisma/e2e.db` (`e2e/global-setup.ts`) |
| Ручной | Браузер, DevTools | — | Визуальное качество, производительность 3D, демонстрационный сценарий | `npm run dev` или `npm run start` |

Рабочая база `prisma/dev.db` тестами не затрагивается.

## 3. Модульные тесты движка (`tests/unit/engine.test.ts`)

Вспомогательная функция `checkInvariants` применяется в большинстве тестов и проверяет инварианты:

- **И1. Сохранение изделий:** `released = completed + scrapped + wipEnd`; число записей с исходом `WIP` равно `wipEnd`; сумма очередей и обработки по участкам на конец горизонта равна `wipEnd`.
- **И2. Загрузка в диапазоне 0..1**, интеграл занятости не превышает `capacity × horizon`, пиковая занятость ≤ вместимости.
- **И3. Неотрицательные длительности:** ожидание, обработка, `exitMin ≥ arrivalMin`.
- **И4. Порядок событий:** время событий журнала не убывает и не превышает горизонт.
- **И5. Кадры состояния:** занятость в каждом кадре ≤ вместимости, очередь ≥ 0.
- **И6. Стоимость ≥ 0.**

| Группа / тест | Что проверяет | Требования |
|---|---|---|
| Воспроизводимость: «один и тот же seed даёт идентичный результат» | Идентичные агрегаты и журнал событий | FR-12, NFR-08 |
| «разные seed дают разные траектории» | Влияние seed | FR-12 |
| «репликации воспроизводимы и первая совпадает с одиночным прогоном» | Детерминизм репликаций, уникальность производных seed | FR-12, NFR-08 |
| Граничные: «нулевой входящий поток → нулевой выпуск, стоимость единицы не определена» | Нулевой поток, `costPerUnitRub = null`, оплата доступности ресурса | FR-11, FR-14 |
| «нулевой выпуск при ненулевом поступлении: операция длиннее горизонта» | Нулевой выпуск, загрузка 100% | FR-14 |
| «корректно завершает горизонт: незавершённые изделия учитываются как НЗП» | Точный подсчёт (12 запущено, 8 завершено, 4 НЗП), последнее событие `HORIZON_END` | FR-11, FR-14 |
| «отклоняет некорректную конфигурацию» | Отрицательный горизонт, нулевая вместимость, неверное треугольное распределение, неизвестная станция, отрицательная ставка | FR-10, NFR-09 |
| Очереди: «без перегрузки очередь не образуется…» | Точная загрузка 12×5/120 | FR-14 |
| «образование очереди при обслуживании дольше интервала поступления» | Рост очереди, ожидание > 0 | FR-11 |
| «параллельные ресурсы: при вместимости 2 очередь исчезает» | Несколько параллельных ресурсов | FR-11 |
| «перегрузка станции: загрузка → 100%, очередь растёт, НЗП накапливается» | Перегрузка | FR-11, FR-15 |
| «ресурс никогда не обслуживает больше заданий, чем вместимость (по журналу событий)» | Вместимость по журналу PROCESS_START/FINISH | FR-11 |
| «время цикла ≥ времени обработки…» | Цикл = обработка + ожидание | FR-14 |
| Качество: «вероятность брака 0 — доработок нет» | Доля брака 0 | FR-11 |
| «брак 100% без доработок: все проверенные изделия списываются» | Списание при `maxReworkCycles = 0` | FR-11 |
| «брак 100%: число доработок ограничено максимумом, бесконечного цикла нет» | Ограничение циклов доработки | FR-11, NFR-09 |
| «доля брака близка к заданной вероятности на длинном горизонте» | Статистическая корректность | FR-14 |
| «журнал содержит события ARRIVAL, QUEUE_ENTER, …» | Полнота типов событий | FR-11, FR-25 |
| Стоимость: «стоимость рассчитывается по документированной модели» | Ресурсы, расходники, компоненты, постоянные, простой | FR-14 |
| «все демонстрационные сценарии выполняются и сохраняют инварианты» | Пять демо-сценариев | FR-34 |

## 7. Ручные проверки

| № | Проверка | Порядок | Ожидаемый результат | Требования |
|---|---|---|---|---|
| Р-1 | Демонстрационный сценарий | Пройти [DEMO_SCRIPT.md](DEMO_SCRIPT.md) на чистой БД (`npm run setup`) | Все шаги выполняются без ручного исправления данных | AC-17 |
| Р-2 | Производительность 3D | Chrome DevTools → Performance, запись 10 с на `/factory` в режимах «Экскурсия» и «Воспроизведение»; переключение качества | Нет длинных задач > 200 мс в установившемся режиме; при «авто» качество снижается на слабом устройстве. **Конкретные значения FPS не заявляются без измерения на целевом устройстве** | NFR-11 |
| Р-3 | Потеря WebGL-контекста | DevTools → Rendering или расширение `WEBGL_lose_context` | Показывается план 2D и сообщение «3D-контекст потерян» | FR-30 |
| Р-4 | Клавиатура и фокус | Tab по мнемосхеме, таблице участков, маршруту тура | Видимый фокус, выбор по Enter/Space | NFR-13 |
| Р-5 | prefers-reduced-motion | Включить эмуляцию в DevTools | Перелёты камеры мгновенные, пульсации отключены | NFR-13 |
| Р-6 | Сенсорный ввод | Планшет/телефон: касание таблички участка, вращение и масштаб жестами | Выбор участка, OrbitControls реагируют на жесты | FR-22, NFR-01 |
| Р-8 | Отказы в 3D | `/factory` → «Воспроизведение прогона» базового сценария, кадр ~04:05 | Над станком в ремонте — ограждение и выноска «Ремонт», в табличке участка «1 в ремонте» | FR-41 |
| Р-10 | Движение изделий | `/factory` → «Воспроизведение прогона», скорость 5 мин/с, «▶» | Насосы на синей подсветке движутся по конвейеру от участка к участку; при reduced-motion — без промежуточного движения | FR-45 |
| Р-9 | Печать отчёта | `/compare` → «Печать / PDF» | В предпросмотре нет навигации и кнопок, панели не разрываются | FR-42 |
| Р-7 | Отображение диаграмм | Открыть `docs/diagrams/process.bpmn` в bpmn.io, Mermaid-файлы в mermaid.live | Диаграммы отображаются без ошибок | — |

## 8. Критерии завершения тестирования

- все модульные и интеграционные тесты проходят (`npm run test`);
- `npm run typecheck` и `npm run build` завершаются без ошибок;
- E2E-тесты проходят на трёх проектах либо причина недоступности окружения зафиксирована в FINAL_REPORT.md;
- ручные проверки Р-1…Р-6 выполнены, результаты записаны в FINAL_REPORT.md.
