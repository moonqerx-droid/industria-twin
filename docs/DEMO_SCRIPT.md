# Сценарий демонстрации (6–7 минут)

Подготовка: `npm run setup && npm run build && npm start`, вход под `engineer` (пароль в README). Все числа на экране рассчитываются симулятором; в сценарии показа нет заранее зашитых значений. Перед показом выполните `npm run report:scenarios` — команда печатает актуальные результаты всех демонстрационных сценариев и их парное сравнение с базовым.

Сквозная история: **«Что ограничивает выпуск цеха и что выгоднее — купить оборудование или навести порядок в обслуживании?»**

| Шаг | Время | Действие | Что сказать |
|---|---|---|---|
| 1 | 0:00 | Открыть **3D-тур** → «Общий план» | Цех из шести участков, поток слева направо. Каждый объект — тот же участок, что в процессе и аналитике. Данные синтетические. |
| 2 | 0:30 | Перейти на **Дашборд** | KPI за две смены с 95% ДИ по 20 репликациям. Узкое место — **механообработка**: загрузка ~82% плюс ~5% времени станки в ремонте (≈5 отказов за две смены). Без учёта отказов узким местом выглядела бы сборка — модель отказов меняет вывод. |
| 3 | 1:10 | Открыть **Процесс** | Мнемосхема: загрузка, очередь, ресурс, стоимость; красный отрезок на полосе узла — доля времени в ремонте. |
| 4 | 1:40 | Дашборд → блок **«Советник по ресурсам»** | Система сама проверила 7 гипотез «+1 ресурс» за доли секунды, с теми же случайными числами, что и базовый прогон. Видно, какие варианты дают различимый эффект, а какие только добавляют затраты (склад, упаковка, доработка). |
| 4а | 2:00 | Ниже — **«Запас мощности»** | Кривая цикла и выпуска при спросе 60–150%. Вывод сверху: текущий спрос уже на ~2% выше установившейся мощности сборки — НЗП растёт в течение смены. При +20% спроса выпуск почти не растёт, а цикл удлиняется на ~40 минут. |
| 5 | 2:20 | Нажать **«Проверить и сравнить»** у рекомендации | Одним действием: сценарий создан, рассчитан, открыто сравнение «до/после». |
| 6 | 2:40 | **Сравнение**: блок вывода и таблица | Зелёный блок — вывод для руководителя: что различимо улучшилось, куда смещается узкое место. «±» — 95% ДИ **парной** разности: благодаря общим случайным числам интервал в 5–10 раз уже, чем при независимых прогонах, поэтому эффект в 7–10 минут цикла статистически значим. |
| 7 | 3:20 | В сравнении отметить «Программа ТОиР (TPM)» и «Повышение качества сборки», «Сравнить» | Организационные меры без закупки оборудования снижают **стоимость единицы** различимо (≈ −900…−1 050 ₽), а дополнительные посты сокращают цикл, но различимо стоимость не снижают. Это и есть управленческий вывод. |
| 8 | 4:10 | «Скачать CSV» / «Печать / PDF» | Таблицу можно унести на совещание. |
| 9 | 4:30 | **3D-тур** → «Маршрут для аудитории»: «Руководство…», остановка «Отказы на мехобработке» | Карточка **кейса**: «ТОиР вместо нового станка» — рассчитанные «до → после» и ссылки «Открыть сравнение» и «Процесс в этом сценарии». Тур не рассказывает, а показывает проверяемые цифры. |
| 10 | 5:10 | «Воспроизведение прогона», протянуть ползунок к ~04:05, скорость 5 мин/с, «▶» | Насосы движутся между участками по журналу событий; очередь растёт; один станок под **красным ограждением «Ремонт»** — отказ из модели, а не анимация «для красоты». Для абитуриентов и новых сотрудников есть свои маршруты тура. |
| 11 | 5:50 | **Сценарии** → «Программа ТОиР», блок отказов на участке B1 | Параметры MTBF/MTTR редактируются, готовность и оценка ρ пересчитываются до запуска. |

## Возможные вопросы жюри

* *Откуда цифры?* — Из симулятора и сохранённых прогонов; параметры видны в сравнении и в «Документации». `npm run report:scenarios` воспроизводит их из командной строки.
* *Почему выпуск почти не растёт при добавлении ресурса?* — Выпуск ограничен входящим потоком заданий; при достаточной мощности растут не штуки, а сокращаются цикл и НЗП.
* *Что такое общие случайные числа и почему им можно верить?* — Это стандартный метод снижения дисперсии в имитационном моделировании: у каждого источника случайности свой поток (поступления; длительность операции изделия k на участке s; исход его контроля; отказы участка). В двух сценариях одно и то же изделие получает одинаковые «случайности», поэтому разница вызвана параметрами. Парный интервал строится по разностям внутри пар репликаций; для несопоставимых прогонов автоматически используется интервал Уэлча.
* *Насколько модель полная?* — Учтены отказы оборудования (MTBF/MTTR, неупреждающая модель); не учтены переналадки, смены, транспорт, приоритеты (см. «Документация → Ограничения»).
* *Что будет без WebGL?* — Открывается план цеха 2D с теми же точками интереса и показателями.
